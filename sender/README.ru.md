# Асинхронная отправка email через RabbitMQ

[English](README.md) · [Русский](README.ru.md)

Пакет для асинхронной отправки email через RabbitMQ. Принимает `EmailTask`, ставит в очередь, воркеры публикуют в брокер с подтверждением доставки. Реальная SMTP отправка выполняется потребителями очереди.

---

## Как работает

1. **`AsyncSend`** ставит задачу во внутреннюю очередь (блокируется если заполнена)
   - Если контекст без таймаута, используется `DefaultSendTimeout` (100ms по умолчанию)
   - Это защищает от бесконечного ожидания при переполненной очереди
   
2. **Воркеры** забирают задачи, публикуют в RabbitMQ с подтверждением
   - Все воркеры работают через одно соединение с сервером
   - Каждый воркер пишет в собственный AMQP канал
   - Используется **confirm mode** — ожидание подтверждения доставки от брокера
   - При разрыве соединения автоматически переподключается с паузой `ReconnectInterval`
   
3. При ошибках задача уходит в **backlog** для повторной отправки
   - Ошибки публикации, отсутствия подтверждения или таймауты
   - Каждая retry-попытка уменьшает счётчик `MaxMessageRetry`
   
4. **Повторные попытки** обрабатываются в приоритете над новыми задачами
   - Воркеры сначала проверяют backlog, затем основную очередь
   - Это гарантирует обработку проблемных сообщений в первую очередь
   
5. **`Close`** корректно останавливает все воркеры и закрывает соединения
   - Прекращает приём новых задач, ждёт завершения текущих операций
   - Использует `ShutdownTimeout` для ограничения времени остановки

## Конфигурация

### `SenderConfig` (`Config.Sender`)

| Поле | За что отвечает |
|------|-----------------|
| **`WorkerCount`** | Сколько горутин-воркеров забирают задачи и публикуют их в RabbitMQ. |
| **`ShutdownTimeout`** | Ограничение по времени при вызове **`Close`** (дополнительно к переданному контексту). Ноль — без отдельного дедлайна, кроме контекста вызывающего. |
| **`DefaultSendTimeout`** | Таймаут по умолчанию для операции отправки сообщения. |

### `WriterConfig` (`Config.Writer`)

| Поле | За что отвечает |
|------|-----------------|
| **`URL`** | Строка подключения к RabbitMQ. |
| **`QueueName`** | Имя очереди при объявлении топологии (durable-очередь). |
| **`ExchangeName`** | Имя direct exchange при объявлении топологии (durable). |
| **`RouteKey`** | Ключ маршрутизации: привязка очереди к exchange и публикация сообщений. |
| **`SetupChannelEachUpdate`** | Объявлять ли при каждом новом канале очередь, exchange и привязку. Если выключено, эта топология уже должна быть на брокере. |
| **`ConnectTimeout`** | Таймаут установки TCP-соединения с брокером. |
| **`ConnectKeepAlive`** | Интервал keep-alive для TCP-соединения. |
| **`HeartBeatTimeout`** | Интервал heartbeat AMQP на соединении. |
| **`ReconnectInterval`** | Пауза после неудачного переподключения или обновления канала перед следующей попыткой. |
| **`MessageConfirmTimeout`** | Сколько ждать подтверждения публикации после отправки; по таймауту отправка считается неуспешной, задача может уйти в повтор через backlog. |
| **`DefaultMessageTTL`** | Время жизни сообщения по умолчанию в RabbitMQ. |

### `StorageConfig` (`Config.Storage`)

| Поле | За что отвечает |
|------|-----------------|
| **`MainPoolMessageCount`** | Размер основной in-memory очереди между **`AsyncSend`** и воркерами. |
| **`BacklogMessageCount`** | Размер очереди backlog для неуспешных задач, ожидающих повторной отправки. |
| **`BacklogMessageWriteTimeout`** | Опциональный лимит времени при записи неуспешной задачи в backlog (чтобы не зависнуть, если backlog долго полон). Ноль — без этого дополнительного ограничения. |
| **`MaxMessageRetry`** | Начальное значение счётчика попыток у задачи; при каждой неудаче и повторной постановке в backlog оно уменьшается. При нуле задача больше не возвращается в очередь. |

Имена переменных окружения для загрузки полей заданы в тегах `env` в `sender.go`, `writer.go` и `messages.go`.

## API

```go
// Basic usage
sender.AsyncSend(ctx, &EmailTask{
    TTL:  5 * time.Minute,  // опционально, иначе DefaultMessageTTL
    Body: jsonEmailData,     // JSON для потребителя
})

// Без контекста или без таймаута - используется DefaultSendTimeout
sender.AsyncSend(context.Background(), task)  // 100ms таймаут
sender.AsyncSend(context.TODO(), task)        // 100ms таймаут

// С явным таймаутом
ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()
sender.AsyncSend(ctx, task)  // 5s таймаут
```

### Методы

- **`New(ctx, cfg, log)`** — создает sender, подключается к RabbitMQ, запускает воркеров
  - Устанавливает соединение и тестирует создание канала
  - Запускает `WorkerCount` горутин для обработки задач
  
- **`AsyncSend(ctx, task)`** — ставит задачу в очередь 
  - Блокирует если основная очередь заполнена
  - Автоматически добавляет `DefaultSendTimeout` если у контекста нет дедлайна
  - Возвращает ошибку если сервис закрыт или контекст отменён
  
- **`Close(ctx)`** — останавливает приём задач, ждёт завершения воркеров
  - Закрывает внутренние очереди, воркеры завершают текущие операции
  - Использует `ShutdownTimeout` как дополнительный лимит времени
